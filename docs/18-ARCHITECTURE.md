# 18 — Architecture (seam index)

## §1 Layer map (today)

- `src/App.tsx` — app shell (no `max-w-3xl` cap; prose blocks are bounded
  locally): ONE compact bar (identity + the in-app tab bar Generate | Gallery |
  Chat | Settings + `ThemeToggle`) and the active tab's surface below it. No
  router. Owns the active tab and BOTH cross-tab channels: the one-shot
  `ChatAttachRequest` the gallery's "Chat with this image" raises (`onChat`),
  which puts the owner on the Chat tab with that image staged (docs/17 row 18),
  and the refine form's mode + source that the gallery's "Refine this" sets
  (`onRefine`) before selecting the Generate tab (docs/17 row 30). The gallery
  is a TOP-LEVEL tab: `Generate` is the form alone, `Gallery` mounts the grid
  (and therefore re-reads the library on every entry).
- `src/features/generate/GenerateArea.tsx` — the generation FORM only: the
  Create | Refine `Segmented` switch (the form's first control) and the active
  panel, bounded locally (`max-w-xl`) and centred rather than stretched. Its
  mode + refinement source are CONTROLLED from `App` (the union lives in
  `src/features/generate/mode.ts`) because the Gallery tab sets both across a
  tab switch. No gallery, no side-by-side split, and no slide-in controls
  sheet: with the artwork gone from this tab there is nothing for a sheet to
  uncover (docs/17 row 30).
- `src/components/styles.ts`, `src/components/ui.tsx` — the design vocabulary
  (button recipe, focus ring, `EmptyState`, `Segmented`, `CopyButton`,
  `SaveButton`); `src/lib/media.ts` — the ONE responsive breakpoint query.
- `src/features/export/` — the export seam (`exportLibrary.ts`) and its Settings
  section (`ExportPanel.tsx`): the ONE place the library leaves the browser as a
  file (docs/17 row 25).
- `src/features/import/` — the import seam (`importLibrary.ts`: read → validate
  → preview → apply) and its Settings section (`ImportPanel.tsx`): the ONE way a
  file gets back INTO the library (docs/17 row 27). Internal format only.
- `src/lib/zip.ts` — the ONE module importing `fflate` (`zipSync` for the export
  seam, `unzipSync` for the import seam); `src/lib/sha256.ts` — the ONE content
  hash, written by the exporter and verified by the importer;
  `src/lib/openFile.ts` — the open-file seam, the mirror of `saveFile.ts`.
- `src/main.tsx` — mounts `App` inside `ErrorBoundary`; imports
  `@fontsource-variable/inter` (self-hosted, no external font request) and
  `index.css`; re-applies the theme through the seam; window `error` /
  `unhandledrejection` → `toastError`. Throws if `#root` is missing.
- `index.html` — the inline pre-paint theme script (the ONLY inline script).
- `vite.config.ts` — `base: '/imager/'`, `@/*` alias, `test.maxWorkers` 2.
- `scripts/gate.sh` — the ONE suite runner (pin `tests/architecture/one-gate.test.ts`).

## §3 Gotchas

- The static host has NO history fallback → Imager uses in-app tabs (the
  Generate | Gallery | Chat | Settings bar, and Create | Refine inside the
  Generate form), never a router
  library. (Owner intent via brief; donor Campaigner uses react-router, which
  does NOT port.) `index.html` must stay small: exactly one inline script (the
  pre-paint theme read) and nothing else.
- Asset base MUST stay `/imager/` — `dist/index.html` must reference
  `/imager/`-based assets, verified by build proof each slice that touches
  config.
- Bare `GET /models` lists TEXT-output models only; image-only models
  (flux, gpt-image, …) need `?output_modalities=all` (measured, docs/17 row 2).
- Model choice is ALWAYS the user's explicit pick. Porting the donor's
  fallback chain must not smuggle in a pinned default.
- A refinement instruction is FREE TEXT sent to the model verbatim — never
  regex-parsed, never used to infer parameters (rule 5).
- The chat path (`/chat/completions`) sends `settings.refineChatModel` and
  NOTHING else: unlike the Images-API refinement (docs/17 row 11), it has NO
  fallback to the image model, because the image model may be generation-only
  (no text out). An empty refinement pick disables the composer with that
  reason.
- A prior turn's generated image is replayed through the assistant message's
  `images` field — the OpenAPI `ChatAssistantMessage.images`, documented "for
  requests and responses" — not as a user content part. The part BODY still
  comes from the ONE `imageUrlPart` builder in `src/llm/images.ts`.
